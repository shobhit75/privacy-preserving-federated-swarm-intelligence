## Project

## Working agreements

- Commit work that can be reviewed: code, experiments, diagrams, decisions, or documentation. Do not make empty or backdated commits to satisfy the schedule.
- Use a short, descriptive commit message, such as `docs: define privacy threat model` or `feat: add federated aggregation prototype`.
- Open a pull request for substantial changes and ask another team member to review it.
- Add a dated entry to [`docs/progress-log.md`](docs/progress-log.md) on each work day. Record work, evidence or links, blockers, and next steps.
- Keep credentials, private datasets, and personal information out of commits.

## Repository layout

- `docs/progress-log.md` — dated team activity log and report outline
- `docs/` — design, research notes, reports, and diagrams
- `src/` — prototype implementation
- `experiments/` — reproducible experiments and results (no private data)
